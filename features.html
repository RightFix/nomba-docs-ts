Advanced features

Past raw HTTP calls.

The generated resource methods cover every endpoint, but a few things needed more than a flat method signature. This page covers all of them.

Pagination

Nomba's list endpoints are cursor-paginated server-side — they return a cursor you feed back in for the next page. paginate drives that loop for you with an async generator; no second pagination scheme is introduced. 

import { Nomba, paginate } from 'nomba-ts'

const nomba = new Nomba({ apiKey: '...', apiSecret: '...', accountId: '...' })

for await (const account of paginate(nomba.accounts.listAllAccounts.bind(nomba.accounts))) {
  console.log(account.accountRef)
}

Confirmed paginated endpoints: accounts.listAllAccounts, accounts.fetchTerminalsAssignedToAccount, accounts.fetchTerminalsAssignedToParentAccount, virtualAccounts.filterVirtualAccounts, and all six transactions.* list/filter methods.

Guided card-payment flow

Card checkout is a multi-step sequence: submit card details, then maybe an OTP, maybe a 3D Secure redirect, then confirm. CardPaymentFlow wraps the sequence and decodes Nomba's response codes into plain booleans, instead of you needing to know what "T0" or "S0" mean. 

const order = await nomba.checkout.createOnlineCheckoutOrder({
  orderReference: 'order-001',
  amount: '1000',
  // ...
})

const flow = nomba.createCardPaymentFlow(order.data.orderReference)
let step = await flow.submitCard({ cardDetails: '...', key: '' })

if (step.requiresOtp) {
  step = await flow.submitOtp('123456')
} else if (step.requires3ds) {
  // redirect the user using step.secureAuthenticationData
}

if (step.completed) {
  const result = await flow.confirm()
}

step is a CardPaymentStep with .completed, .requiresOtp, .requires3ds, .transactionId, .message. nomba.createCardPaymentFlow(...) returns a CardPaymentFlow instance.

Webhook signature verification

Implements Nomba's documented HMAC-SHA256 scheme (nomba-signature / nomba-timestamp headers, base64-encoded signature) plus a replay-window check on the timestamp — a valid signature alone doesn't prove a webhook wasn't captured and resent later. 

import { verifyWebhookRequest, NombaValidationError } from 'nomba-ts'

app.post('/webhooks/nomba', (req, res) => {
  try {
    const payload = verifyWebhookRequest('your-signature-key', {
      body: req.body,  // raw string or Buffer
      headers: req.headers as Record,
      maxAgeSeconds: 300,  // default; reject webhooks older than 5 min
    })

    if (payload.event_type === 'payment_success') {
      // ...
    }
    res.sendStatus(200)
  } catch (e) {
    if (e instanceof NombaValidationError) {
      res.sendStatus(401)  // invalid signature or stale timestamp
    }
  }
})

Pass maxAgeSeconds: null to disable the replay check if you have your own.

Local request validation

Flat fields are enforced by TypeScript itself. But nested objects — like request bodies in checkout order creation — have their own required fields that TypeScript can't check at the type level. Every write call (POST/PUT) is validated against Nomba's bundled OpenAPI spec before any network call. 

import { NombaValidationError } from 'nomba-ts'

try {
  await nomba.checkout.createOnlineCheckoutOrder({ orderReference: 'x' })
} catch (e) {
  if (e instanceof NombaValidationError) {
    console.log(e.message)
    // Missing required field(s) in request body: amount, currency, ...
    console.log(e.missing)  // ['amount', 'currency']
  }
}

Reliability: locking + retry/backoff

The HTTP client guards token fetching with a lock, so concurrent requests never race to re-fetch a token — only one fetch happens, the rest reuse it. Requests that hit a 429 or transient 5xx retry automatically with exponential backoff, respecting Retry-After when Nomba sends one. 

const nomba = new Nomba({
  apiKey: '...',
  apiSecret: '...',
  accountId: '...',
  maxRetries: 3,      // default
  retryDelay: 1000,   // default; delay ~= retryDelay * 2^attempt
})

Bounded concurrency for fan-out calls

Promise.all has no built-in concurrency limit. Firing off many calls at once can trigger a retry storm if several start failing together, or just trip Nomba's rate limit by bursting too many requests in one window. gatherLimited runs the same calls with a cap. 

import { gatherLimited } from 'nomba-ts'

const calls = accountRefs.map((ref) => () => nomba.virtualAccounts.fetchVirtualAccount(ref))
const results = await gatherLimited(calls, { limit: 5, returnExceptions: true })
// results: (FetchVirtualAccountResponse | Error)[]
